# Chapter 7: Deployment Configuration

In [Chapter 6: Requirements Management](06_requirements_management_.md), you learned how to declare all the Python packages your agent depends on. Your agent knows *what libraries* it needs to run.

But here's a new problem: **When your agent runs in the cloud, how much computing power should it get? How many copies should run at once? What if 1000 people try to use your agent simultaneously?**

Imagine you're opening a restaurant. You need to decide:
- How many tables to set up during lunch rush (busy times)
- How many tables to keep set during late night (slow times)
- How many chairs and place settings per table

You don't want 100 tables when only 5 customers show up—that wastes money. But if 500 customers arrive and you only have 10 tables, they'll leave angry. You need to **find the right balance.**[1]

**Deployment Configuration solves this problem.** It's a settings file (`.agent_engine_config.json`) that tells the cloud: "Here's how much CPU and memory each copy of my agent needs, and here's the minimum and maximum number of copies to run."[1]

Think of it as your agent's **capacity planning document**—the blueprint that ensures your agent has enough resources to handle traffic without wasting money on idle capacity.

## The Problem: From Testing to Real Users

Let's make this concrete with a real example.

**On your laptop (testing):**
```
Your agent uses: ~500MB memory, barely touches CPU
Response time: 2 seconds
```

**In production with real users:**
```
- 9 AM: 100 users asking questions simultaneously
- 12 PM: 50 users (lunch break)
- 3 AM: 1 user (night owl)
```

**Without configuration (the wrong way):**
```
❌ Always run 10 copies → Costs $100/day
   but only 1 copy is needed most of the time

❌ Always run 1 copy → Works fine at 3 AM
   but crashes at 9 AM with 100 users
```

**With deployment configuration (the right way):**
```
✅ Auto-scale from 0 to 5 copies based on demand
✅ Pay $0 when nobody's using it (min_instances=0)
✅ Never pay for more than 5 copies (max_instances=5)
✅ Each copy gets 1 CPU and 1GB memory (enough for agent)
✅ Handles 9 AM rush AND 3 AM quiet time perfectly
```
